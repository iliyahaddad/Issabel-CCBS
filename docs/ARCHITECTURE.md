# Architecture

## Design choice
Asterisk's built-in Call Completion Supplementary Services (CCSS) is used instead of a parallel daemon/database polling phone state. CCSS owns the state machine, timers, limits and race handling.

## Where each piece lives

| Piece | File | Why there |
|---|---|---|
| CC policies (`cc_agent_policy=generic`, `cc_monitor_policy=generic`, timers, `cc_callback_sub`) | `sip_general_custom.conf` (managed block) | `ccss.conf.sample`: these options "should NOT be set in this file; set per-device in a channel driver configuration file". Issabel includes `sip_general_custom.conf` into `[general]` of `sip.conf`, so every chan_sip peer inherits them. |
| Busy hook + offer logic + callback sub | `extensions_override_issabelpbx.conf` (managed block) | Loaded before generated dialplan; never regenerated by the GUI. |
| Prompts | `/var/lib/asterisk/sounds/<prompt_root>/` | Replaceable without touching logic. |
| Local settings | `/etc/asterisk/issabel-ccbs.conf` | Read by `install.sh`, rendered into the two blocks above. |

## Busy hook
```
macro-dial-one:  s-BUSY,1  ->  Gosub(ccbs-offer,s,1)      (original priority 1 is shadowed)
                 s-BUSY,2+ ->  Issabel's original handling (busy tone / voicemail) - still reachable
ccbs-offer:      kill switch? -> skip (Return)
                 caller not a registered Issabel device? -> skip (Return)
                 Answer, play busy + offer, Read 1 digit
                   digit != accept_digit -> play "cancelled", Return  (original busy handling continues)
                   digit == accept_digit -> CallCompletionRequest()
                        SUCCESS -> UserEvent, play "accepted", Hangup
                        FAILURE -> UserEvent, play "failed", Return
```
Taking over only priority 1 (instead of the whole branch) is what keeps voicemail-on-busy working. The cost: Asterisk logs a harmless "Unable to register extension ... already in use" warning on dialplan reload.

## Lifecycle after acceptance
The generic agent remembers the caller's device; the generic monitor watches the callee's device state (needs `callcounter=yes`). When the callee becomes free, Asterisk rings the caller (`cc_recall_timer`), runs `cc_callback_sub` (`ccbs-callback`) when the caller answers, then dials the callee.

## Limits of Generic CCSS (by design of Asterisk)
- One outstanding request per generic agent (caller); `cc_max_agents` is ignored.
- Only for phones, not trunks; chan_sip only (no PJSIP support in Asterisk).
- The recall dials the device directly (`SIP/101`), so Issabel features on that leg (follow-me, call-forward) are bypassed.
- Fully automatic bridging with no human answer is not part of CCSS; that would need an AMI/ARI service.

## Why no external AMI daemon?
Duplicate originates, device-state races, persistence, stale requests, credentials and recovery after restart are all handled by CCSS already.
